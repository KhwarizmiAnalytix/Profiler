# Phase 5 — what remains

Tracks what is still open from [`design-review.md`](design-review.md)
[section 7, Phase 5](design-review.md#phase-5--simplify-the-supported-api-and-dependencies)
after the 2026-09-18 execution pass (commits `f8a8746`..`f07f3bd`). Full
reasoning for every decision below is in
[`docs/plans/phase-5-api-simplification.md`](plans/phase-5-api-simplification.md)'s
amendments; this file is a short pointer, not a replacement for that record.

Phase 5's original text specified four bullets and a "Done when" clause.
Each remaining item below traces back to one of them.

## 1. Statistics consolidation

> Consolidate statistics and deprecate unused types/fields from the inventory.

The unused-fields half is done (see the plan's 5.B). The consolidation half
is not: `stat_with_percentiles` (`native/analysis/stats_calculator.h`) and
`statistical_analyzer` (`native/analysis/statistical_analyzer.h`) remain two
separate representations. Investigated and declined, not overlooked —
`stat_with_percentiles` computes nearest-rank percentiles,
`statistical_analyzer` linearly interpolates; forcing one onto the other
would silently change existing callers' numbers, not just their code path.

**To pick this up:** decide the target percentile semantics first (or give
`stat_with_percentiles` a second, interpolated mode), then re-evaluate
whether `statistical_analyzer` can safely project from it.

## 2. Real CMake package export

> Replace hard-coded shared-only package metadata with proper exported CMake
> targets for supported shared/static configurations.

Not done. `ProfilerConfig.cmake` is still generated by a hand-rolled
`file(GENERATE ...)` block in `CMakeLists.txt`, not
`install(EXPORT ProfilerTargets ...)` + `write_basic_package_version_file()`.
Declined because doing this properly means the `Profiler` target's usage
requirements (include dirs, link libraries) need to be real target
properties, not a string template assembled at install time — a
restructuring of how the target itself is defined, not just how it's
exported. The Windows `IMPORTED_IMPLIB` leg and the static
whole-archive/registration-preservation trick
(`profiler_keep_static_registrations()`) can't be verified on macOS.

**To pick this up:** needs a Windows machine (or CI) to verify the rewrite
doesn't regress the IMPORTED_IMPLIB path, and a re-run of the static
archive-linking regression test that first caught the registration-drop bug.

## 3. CUDA/HIP static consumption

> (same bullet as #2) proper exported CMake targets for supported
> shared/static configurations.

`find_dependency(CUDAToolkit)` (and the HIP equivalent) is not wired into
the generated package config. A STATIC build with
`PROFILER_GPU_BACKEND=cuda` or `=hip` cannot currently be consumed via
`find_package(Profiler)` — only `PROFILER_GPU_BACKEND=none` is covered by
CI's `static-link` job. This machine has no CUDA toolkit, so nothing was
attempted rather than adding wiring that can't be built, installed, or
consumed to prove it works.

**To pick this up:** needs a machine with the CUDA toolkit (and separately,
HIP/ROCm) to write and verify the `find_dependency()` wiring end to end.

## 4. Compatibility-header transition mechanism

> Publish supported headers only; preserve compatibility headers for the
> stated transition period.

The first half is done (`docs/plans/phase-5-api-simplification.md`'s 5.C):
`install()` now installs exactly the 29 headers `profiler.h` transitively
needs, not every header under `Profiler/`. No compatibility-header opt-out
flag (e.g. a `PROFILER_INSTALL_COMPATIBILITY_HEADERS` option) was built,
because nothing currently needs it — 5.B's removals were outright deletions
of dead code, not deprecations of headers a consumer might still include
directly. Narrowing `install()` aligned the build with documentation
(`profiler.h`'s own doc comment, `docs/profiler.md`) that already described
those headers as internal.

**To pick this up:** only relevant the next time a genuinely public header
needs to be phased out from under a live consumer. Build the mechanism
then, against a real case, rather than speculatively now.

## 5. Publish costs for optional features

> Verify native-only consumption does not initialize or require
> GPU/instrumentation backends. Publish costs and support for optional
> memory/stack/marker features.

The native-only verification half is done — and found a real bug in the
process (see the plan's 5.E amendment: an unguarded `cudaStubs()` call broke
`PROFILER_BACKEND=NONE` on macOS, silently masked on Linux CI by linker
leniency). **The "publish costs" half was not addressed in this pass at
all.** No documentation quantifies the overhead of `with_stack`, memory
tracking, or marker sinks (ITT/NVTX) as distinct, measured cost tiers.

**To pick this up:** extend `profiler_benchmark`
(`benchmarks/profiler_benchmark.cpp`, see `docs/benchmarking.md`) with
per-feature configurations (stack capture on/off, memory tracking on/off,
marker sinks on/off) and publish the resulting cost table in
`docs/benchmarking.md` or `docs/profiler.md`.

## 6. Benchmark re-verification

Not a distinct bullet, but implied by the "Done when" clause's
"compatibility work does not regress performance or reliability gates."
This pass verified correctness (build + test green on `build_ninja`,
`build-itt`, and a throwaway `PROFILER_BACKEND=NONE` build, clang-tidy
clean) but did not re-run `profiler_benchmark` to confirm the header
restructuring and field removals didn't move the needle on Phase 0's
1%/3%/5% overhead budgets. Build/test passing is not the same evidence as a
benchmark run — the same distinction Phase 3's own scope caveat already
draws (`docs/plans/phase-5-api-simplification.md`'s predecessor phase notes
this gap was never fully closed).

**To pick this up:** run `profiler_benchmark` before/after this phase's
commits on the reference machine `docs/benchmarking.md` describes, and
record the result there.

## 7. `session_options`/`capture_config` audit

> Audit all remaining public options for an effect or explicit rejection.

`profiler_options` was fully audited and cleaned in this pass (5.B).
`session_options` (12 fields) and `capture_config` (7 fields) were audited
by the baseline plan's own research before execution ("every field has a
traceable, real effect — no dead fields found in either") but not
independently re-verified during execution.

**To pick this up:** low priority given the baseline audit's finding, but a
fresh pass would close the gap between "audited once, before the fact" and
"independently confirmed."

## What's already done (for contrast)

Native-only isolation (verified empirically + CI-enforced, not just
asserted), dead-field/type removal across the section 4 inventory, the
Python tracer stub's honest-failure behavior, header-set curation, ~11 dead
obsolete-comment remnants removed, and per-backend GPU capability reporting
(`cuda_device_available`/`hip_device_available`) are all done and verified
— see the plan document's validation checklist for the full list and
evidence.
